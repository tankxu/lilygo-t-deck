# 自检应用(Self-Test)

## 设计原则

**每一项都必须由人的动作产生证据才算通过,不读寄存器状态交差。**

"I2C 能 ping 到 0x55" 只证明键盘 MCU 活着,不证明第 3 排第 5 个键的触点没氧化;
"ES7210 初始化返回 ESP_OK" 不证明麦克风膜片没被摔坏。
所以每一站都是一个**必须做完才能通过的小游戏**。

## 七站

### 1. 键盘

屏幕上画 T-Deck 的 QWERTY 缩略布局,每个键一个小方块。

- 按下哪个键,哪个方块从灰变绿,并在中央大字回显该键字符
- 底部进度 `37 / 57`
- 全绿 = PASS
- 长按 `ESC` 跳过(记 SKIP,不记 PASS)

抓的是:单键失效、连键、串扰(按 A 亮了 S)。

### 2. 轨迹球

中央一个光标,四方向滚动推着它走;四角各一个靶区。

- 把光标推进某个靶区 → 该方向判定通过,靶区点亮
- 四个方向全亮 + 中键按下一次 → PASS
- 中键按下时中心圆闪一下

抓的是:某一路方向脉冲不通(T-Deck 轨迹球的常见故障)、中键接触不良。
比"打印 GPIO 电平"强的地方在于:它同时验证了**方向映射有没有接反**。

### 3. 触摸

一块画布,手指划线留下轨迹。

- 四角各一个热区,必须都划到(验证边缘精度,GT911 没校准时边缘最容易飘)
- 再要求一次长按(验证按压时长判定)
- 全部命中 → PASS

### 4. 麦克风

实时 VU 电平条 + 简易频谱柱。

- 对着说话,要求电平超过阈值并**维持 1 秒** → 亮度计判定通过
- 然后自动录 3 秒,进度条显示

抓的是:麦克风完全没声(ES7210 配错)、电平过低(增益没设)、单边通道死掉。

### 5. 喇叭

两步,第二步是整个自检里最有价值的一项:

1. 播放 440Hz → 1kHz → 4kHz 扫频,你按键确认"听到了"
2. **回放第 4 站刚录的那 3 秒** —— 这是麦克风 → I2S → PSRAM → I2S → 功放的
   **端到端闭环**,一次跑通就等于整条音频链路通了,这正是小智能不能跑的前提

听到自己的声音 → PASS。

### 6. 屏幕

RGB 三张纯色 + 16 级灰阶条 + 全白/全黑坏点检查,按键翻页确认。

### 7. 汇总

| 项目 | 结果 |
|---|---|
| 键盘 | PASS 57/57 |
| 轨迹球 | PASS |
| 触摸 | FAIL 左下热区未命中 |
| 麦克风 | PASS 峰值 -12dBFS |
| 喇叭 | PASS |
| 屏幕 | SKIP |

- 单项可重测(选中回车重进那一站)
- 结果可存到 storage 分区,方便对比"上次还好好的"

## 为什么这个应用值得优先做

它是 **M1(BSP)的验收标准**。BSP 每写完一个驱动,自检里就多亮一站;
七站全绿 = 驱动层可以交付给 launcher 和小智了。

换句话说,它不是"以后有空做的小工具",而是 bring-up 阶段的主力测试夹具。
所以排在 M2 的 launcher 之前完成大部分。
